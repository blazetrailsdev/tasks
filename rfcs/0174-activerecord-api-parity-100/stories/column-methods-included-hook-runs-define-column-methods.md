## Context

The story `pg-column-methods-primary-key-lives-on-table-definition-not-the-module` made `ColumnMethods` a
`Module` in `packages/activerecord/src/connection-adapters/abstract/schema-definitions.ts` and
`postgresql/schema-definitions.ts`, holding `primaryKey` once and mixed in with `include()`.

Rails' modules also run `define_column_methods` from their `included do` block
(`vendor/rails/v8.0.2/activerecord/lib/active_record/connection_adapters/abstract/schema_definitions.rb:323-329`,
`postgresql/schema_definitions.rb:184-189`, `mysql/schema_definitions.rb:45-51`), and define it once
under `class_methods do` (`abstract/schema_definitions.rb:331-343`). The port still calls
`TableDefinition.defineColumnMethods(...)` and `Table.defineColumnMethods(...)` as top-level statements,
once per class, with the `blob` / `numeric` aliases beside them, and `defineColumnMethods` is a static
written twice (a sync body on `TableDefinition`, an async one on `Table`).

It was left because `collectDefineColumnMethodsMembers` in `scripts/api-compare/extract-ts-api.ts`
credits the generated members only from a top-level `Klass.defineColumnMethods("a", ...)` statement on
an identifier receiver. Moving the calls into an `[included](base)` hook dropped 48 credited methods
(`abstract/schema_definitions.rb` 134 to 118, `postgresql/schema_definitions.rb` 70 to 38).

MySQL's `ColumnMethods` (`mysql/schema-definitions.ts`) is still a type-only interface.

## Acceptance criteria

- [ ] The extractor credits members generated by a `defineColumnMethods` call inside a module's
      `[included]` hook to every class that includes the module.
- [ ] The abstract, PostgreSQL and MySQL `ColumnMethods` modules run `defineColumnMethods` and the
      aliases from `[included]`, and no top-level `Klass.defineColumnMethods(...)` statement remains.
- [ ] `pnpm parity:api` reads 100% for the three `schema_definitions.rb` files.
