## Context

`tsc --strict` over an app generated by `AuthenticationGenerator` (from the built
dist, PR trails#8106) reports errors in code trails itself emits
(`packages/trailties/src/generators/rails/authentication/templates.ts`):

- `redirectTo(url, { alert | notice })`: `alert` / `notice` are not in the
  `redirectTo` options type (`{ status?, allow_other_host? }`). Rails'
  `redirect_to` takes flash types registered by `add_flash_types`
  (`actionpack/lib/action_controller/metal/flash.rb:37-52`, `redirect_to` at `:54-66`).
- `rateLimit({ within: minutes(3) })`: `Duration` is not assignable to `number`
  (`actionpack/lib/action_controller/metal/rate_limiting.rb`, `within:` is a Duration).
- `Current.session` is not a property on `typeof Current`. `CurrentAttributes.attribute`
  generates class-level readers (`activesupport/lib/active_support/current_attributes.rb`)
  that the emitted `Current` does not type.
- `beforeAction("setUserByToken", { only })`: a string is not assignable to `ActionCallback`.
- `User.findByPasswordResetTokenBang` does not exist on `typeof User`; `has_secure_password`
  generates `find_by_password_reset_token!` (`activerecord/lib/active_record/secure_password.rb`).
- `hasSecurePassword` does not exist on `typeof User`, and `normalizes`' `with:` rejects
  a `(e: string) => string` lambda.
- `this.params.get(...)` is typed `unknown`, which fails at the `update` call.

## Acceptance criteria

- `tsc --strict` over a freshly generated authentication app reports no errors
  other than those caused by the unported mailer (covered by
  `passwords-mailer-resolves-against-a-ported-actionmailer`) — including the one
  that surfaces at the `PasswordsMailer.reset(user).deliverLater()` call site in
  `app/controllers/passwords_controller`, since the mailer's `reset` is `unknown`.
- Each fix lands on the framework type that is wrong, not as a cast in the template.
- A test type-checks the generated output, not just `parseTs` syntax.
