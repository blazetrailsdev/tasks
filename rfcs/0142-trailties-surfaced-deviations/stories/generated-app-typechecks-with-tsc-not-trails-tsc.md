## Context

Found by the trailmap Rails-idiom audit. The repo README sells zero-declare
models (`README.md` "Zero-declare models — `trails-tsc`"): `trails-tsc --schema db/schema.ts`
synthesizes attribute, association, scope and enum members, "so you never
hand-write a `declare`". The generated application doesn't use it.
`packages/trailties/src/generators/app-generator.ts:155` emits
`build: "tsc"`, even though the same generator adds `@blazetrails/trails-tsc`
as a devDependency (`:177`) and wires its views plugin into `tsconfig.json`
(`:204`).

So a generated app's models typecheck only if the author hand-writes
`declare` lines. trailmap, generated from this template, carries about 60 of
them: `app/models/story.ts:52-89` (every column, every association proxy, the
enum-generated `ready()`/`isDone()`), `app/models/rfc.ts:33-51`,
`app/models/event.ts:12-19`, `app/models/joins.ts`, `app/models/meta.ts:8-9`.
None of them appear in the Rails model they mirror.

The trailmap CI story (`set-up-ci-for-trailmap`, done) intended
`trails-tsc --schema db/schema.ts` to be trailmap's typecheck. It shipped with
plain `tsc`, which is consistent with following the generator.

## Acceptance criteria

- The generated `package.json` typechecks with `trails-tsc --schema db/schema.ts`
  (the invocation the README documents). A model generated by
  `trails generate model` typechecks with no `declare` lines.
- A generator test asserts the `build` / typecheck script, and a boot-app
  fixture model with a column, an association and an enum typechecks under the
  generated script with zero `declare`s.
