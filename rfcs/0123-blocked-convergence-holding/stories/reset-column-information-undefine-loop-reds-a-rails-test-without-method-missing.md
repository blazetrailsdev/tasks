## Context

`ModelSchema#reset_column_information`
(`vendor/rails/v8.0.2/activerecord/lib/active_record/model_schema.rb:523-530`) runs
`([self] + descendants).each(&:undefine_attribute_methods)` at `:525`. The port
(`packages/activerecord/src/model-schema.ts`, `resetColumnInformation`) omits the loop, and
`pnpm parity:api:arms:report --package=activerecord --direction=missing` reads `-loop`.

The loop was added in trails#8717 and taken out again, because it reds a Rails test on all three
adapters:

```ruby
test "resetting column information doesn't remove attribute methods" do
  topic = topics(:first)
  assert_not_predicate topic, :id_changed?
  Topic.reset_column_information
  assert_not_predicate topic, :id_changed?
end
```

(`vendor/rails/v8.0.2/activerecord/test/cases/base_test.rb:1770-1778`, ported in
`packages/activerecord/src/base.test.ts`). With the loop, the second read fails with
`TypeError: t.idChanged is not a function`.

In Rails the undefined method comes back through `method_missing` on the existing record. Root
`CLAUDE.md` § "Records are not Proxies" rules that out for trails: a generated reader removed by
`undefineAttributeMethods` is not regenerated by reading it off an existing record, only through
`defineAttributeMethods` or construction. So the faithful loop and this Rails test cannot both
hold, and every record alive across a `resetColumnInformation` loses its generated readers until
the next construction.

This needs an owner decision between:

- port the loop and park the test's second assertion under a `PERMANENT-SKIP:` line citing that
  section, accepting the window in which live records have no readers; or
- keep the omission and receipt it (`@missingRailsCall undefine_attribute_methods`), with the
  section amended to name it; or
- port the loop and have `resetColumnInformation` regenerate eagerly, which is a call Rails does
  not make and needs its own receipt.
