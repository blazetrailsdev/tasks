## Context

trails#9193 seated `sanitized_allowed_tags=` / `sanitized_allowed_attributes=` in `packages/html-sanitizer/src/rails-html-sanitizer.ts`, the mirror of `vendor/rails-html-sanitizer/v1.6.2/lib/rails-html-sanitizer.rb:14-36`. The rest of that `ClassMethods` reopen is unported: `:38-49` defines `sanitized_protocol_separator`, `sanitized_uri_attributes`, `sanitized_bad_tags`, `sanitized_allowed_css_properties`, `sanitized_allowed_css_keywords`, `sanitized_shorthand_css_properties` and `sanitized_allowed_protocols` (reader and `=` writer each), and all of them call the private `deprecate_option` (`:51-57`), which warns through `ActiveSupport::Deprecation.warn`. html-sanitizer does not depend on activesupport.

## Acceptance criteria

- Each of the 7 names gets a reader and a `setX` writer on the gem's `ActionView.Helpers.SanitizeHelper.ClassMethods` in `rails-html-sanitizer.ts`, generated by a loop as in Rails, each calling a private `deprecateOption(name)` that issues the Rails warning text verbatim.
- The deprecation path goes through ActiveSupport's deprecator (add the dependency, or seat it via a namespace read if a dependency would make a cycle).
