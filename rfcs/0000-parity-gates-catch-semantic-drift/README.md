# RFC — Parity gates catch the drift the Writebook port found

## Summary

Porting Writebook (trails#10716) surfaced framework bugs in nine packages,
extracted as trails#10792. No parity gate caught any of them. The gates compare
names, call sets, call arguments, parameters, arms and test names. They do not
compare return values, the methods a Ruby macro generates, the meaning of a JS
built-in that shares a Ruby name, or whether a ported name reaches a package's
public entry. This RFC adds a gate or lint rule for each of the four, and
typechecks the example apps in CI so a type-only gap reds before an app finds it.

## Design

### 1. A block-returning method that returns `void` reds

`parity:api:returns` gains a gated arm. It does not depend on a Rails caller: a
Ruby method whose final statement is a `yield`, or a call that passes the
method's own block on (`transaction(**opts) do … yield end`,
`with_connection(&block)`), returns that block's value by construction. Its port
is a `void` / `Promise<void>` only in error. The extractor already walks
bodies (`extract-ruby-api.rb`); it records a `returnsBlock` flag per method, and
the gate pairs it with `signatureReturnsVoid` (`extract-ts-api.ts`). The gate is
only-shrink with a per-package mark, like the other ratchets. The caller-based
report stays as it is.

### 2. `delegate_missing_to` generates its pair in the Ruby manifest

`process_delegate` records `method_missing` and `respond_to_missing?` on the
owner for `delegate_missing_to <target>`, the two methods
`Module#delegate_missing_to` defines
(`activesupport/lib/active_support/core_ext/module/delegation.rb`). A port that
calls `delegateMissingTo` is credited for both
(`packages/activesupport/lib/delegation.ts#generateMethodMissing` defines both).
A hand-rolled Proxy is then a missing pair, and `Attached::One` converges onto
`delegateMissingTo`.

### 3. `Function.name` is not `Module#name`

A lint rule, `blazetrails/no-function-name-as-module-name`, reports a `.name`
read on a value typed as a class constructor in a package's `lib/`, and names
`rbModName` (ruby-compat) as the fix. `rbModName` answers the qualified Ruby
path, which `Module#name` is. A read that only wants JS's short name (a stack
frame, a test label) takes `@noRailsEquivalent`. The rule enrolls packages
through an only-grow set, as the ruby-compat native rule does.

### 4. A ported public name reaches the package entry

`pnpm parity:api:exports` resolves, for every matched public Ruby method,
module and constant whose TS counterpart is a top-level export, whether the
package's `exports` entry (`package.json`) reaches it. A pair that does not is
a row. The gate is only-shrink. A name Rails reaches only through `include`
(a helper method on a view) counts as reached when its module is.

### 5. The example apps typecheck in CI

A CI job runs `pnpm typecheck` in every `examples/*` app that has a
`typecheck` script, on any change under `packages/`. A type the framework
publishes wrong reds there, in the PR that changes it, rather than in the next
app port.

## Non-goals

- **Runtime values of trails-only code.** The Vite URL and the Node handler's
  header loop have no Ruby body to compare against. Their own tests are the
  only check; the trailing-slash test asserted the bug and was fixed with it.
- **A general return-type gate.** Comparing every Ruby return value with a TS
  return type is the 712-row, zero-real-finding filter
  `report-void-returns.ts` already rejected. Design 1 gates only the shape that
  is never a false positive.

## Alternatives considered

- **Gate the caller-based `parity:api:returns` report.** It cannot see a value
  only applications read, which is the `with_lock` case.
- **Typecheck one example app only.** Writebook found what the other examples
  did not; each app reaches different surface.

## Rollout

1. `returns-block-value-gate`, `delegate-missing-to-in-ruby-manifest` (it
   converges `Attached::One`), `no-function-name-as-module-name`.
2. `parity-api-exports-gate`.
3. `examples-typecheck-in-ci`.

## Verification

- With trails#10792 reverted, each of its fixes reds at least one gate from
  this RFC, except the two named under Non-goals.
- Every new gate lands green on `main`, its rows baselined only for code that
  predates it, and each mark only-shrink.

## Open questions

1. **Rack header nil values.** WEBrick's loop (`vendor/rackup/v2.2.1/lib/rackup/handler/webrick.rb:127-134`)
   does not skip nil, and Rack::Lint rejects a non-String header value. Is
   skipping nil in the Node handler (trails#10792) the right fix, or should the
   app-side `nil` be fixed and the handler raise as Lint would? Recommendation:
   decide in trails#10792's review; out of scope here.
