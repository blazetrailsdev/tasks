## Context

Split out of `ruby-compat-marshal-core-types` for size: the both-ways port with
its fixtures and tests measured about 1,540 LOC against an 800 ceiling, so that
story shipped `Marshal.dump` only (`packages/ruby-compat/src/marshal.ts`,
`marshal.trails.test.ts`, `marshal.fixtures.rb` / `.json`). This story is
`Marshal.load`, MRI's `marshal_load` (`vendor/ruby/v3.3.11/marshal.c:2434`)
over `rb_marshal_load_with_proc` (`:2378`) and `r_object_for` (`:1868`).

The load half is already written and passing against Ruby-generated bytes. It
is on the pushed branch `ruby-compat-marshal-load-wip` (commit `f1b2021f6a`,
not a PR): `marshal.ts` from `tooShort` through `rObject`, `Marshal.load`, the
load tests and the three load-only fixtures (`string binary`,
`string us-ascii`, `string shift_jis`). Start from that branch's files rather
than re-deriving them. The same commit carries a port of `rb_path_to_class`
(`vendor/ruby/v3.3.11/variable.c:432-481`) in `variable.ts` with tests, written
before `ruby-compat-constant-table-and-path2class` was found to own it. Use
whichever of the two has landed.

`TYPE_OBJECT` resolves its class through `path2class` (`marshal.c:1790`) over
`rb_path_to_class`, which is why this story depends on
`ruby-compat-constant-table-and-path2class`. The dump side's `class2path`
(`marshal.c:273`) shipped without its
`rb_path_to_class(path) != rb_class_real(klass)` check (`:279`) for the same
reason, and its JSDoc points here.

Decisions already taken on the dump side, which the load side has to match:

- Marshalled data is an ASCII-8BIT String, one character per byte
  (`string/b.ts`'s convention). A String with no `E` / `encoding` ivar loads
  as that byte form, and one with the ivar is re-read through `forceEncoding`.
  `rb_enc_associate_index` retags a Ruby String in place and a JS string is
  immutable, so `r_ivar` answers the re-read string and the `TYPE_IVAR` arm
  re-enters it at its `arg->data` index.
- A Hash loads as ruby-compat's `Hash` (a `Map`), which carries the
  `TYPE_HASH_DEF` default. A whole-valued Float loads boxed (`rbDbl2num`), and
  a Bignum goes through `rbBigNorm`.
- `Marshal.load`'s `proc` and `freeze:` have no call site (README rule 1), so
  `r_leave` (`marshal.c:1693`), `r_post_proc` and `partial_objects` are not
  ported. Neither are the arms `w_object` does not write: `TYPE_USRMARSHAL`
  (owned by `ruby-compat-has-no-marshal-for-schema-cache-and-debug`),
  `TYPE_USERDEF`, `TYPE_DATA`, `TYPE_UCLASS`, `TYPE_EXTENDED`, Regexp, Struct,
  Class and Module. They take `r_object_for`'s `default:` arm.

## Acceptance criteria

- [ ] `Marshal.load(source)` reads a String source for: nil, true, false,
      `TYPE_FIXNUM`, `TYPE_BIGNUM`, `TYPE_FLOAT`, `TYPE_STRING` (with and
      without `TYPE_IVAR`), `TYPE_SYMBOL`, `TYPE_SYMLINK`, `TYPE_LINK`,
      `TYPE_ARRAY`, `TYPE_HASH`, `TYPE_HASH_DEF` and `TYPE_OBJECT`
      (`rbPathToClass`, then `Object.create(klass.prototype)` and
      `rbObjIvarSet`).
- [ ] MRI's errors, with MRI's messages: `TypeError` "incompatible marshal
      file format (can't be read)…" and "instance of IO needed";
      `ArgumentError` "marshal data too short", "dump format error
      (unlinked)", "bad symbol", "dump format error(0x…)", "dump format error
      for symbol(0x…)", "… does not refer to class".
- [ ] `class2path` gains its `rb_path_to_class` check
      (`TypeError "<path> can't be referred to"`), and its JSDoc stops citing
      this story.
- [ ] Every fixture in `marshal.fixtures.json` loads to the value the dump
      test dumps, the three load-only String fixtures are added to
      `marshal.fixtures.rb`, and the README `Marshal` row is updated.
