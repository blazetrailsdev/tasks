## Context

`packages/actionpack/src/abstract-controller/trailties/routes-helpers.ts`
declares an optional interface member `trailtieRoutesUrlHelpers` on
`RoutesHelpersClassMethods`. Rails does not declare it there: it is generated by
Rails::Engine at
`vendor/rails/railties/lib/rails/engine.rb:417`
(`define_method(:railtie_routes_url_helpers) { |include_path_helpers = true|
railtie.routes.url_helpers(include_path_helpers) }`), and
`routes_helpers.rb:15-16` merely probes for it with `respond_to?`.

So the trails declaration is a host-side hook slot standing in for surface that
belongs to `packages/trailties`. `grep` finds no `routesUrlHelpers` in
`packages/trailties/src/engine.ts` today, so the real method is unported. That
is what the `trailtieRoutesUrlHelpers` `@noRailsEquivalent` tag (PR #5367)
records.

Note the deliberate repo-wide `railtie` -> `trailtie` rename: the ported name is
`trailtieRoutesUrlHelpers`, and the Rails-name mapping for it should be
confirmed against `scripts/api-compare/conventions.ts` so `api:compare` pairs
them rather than reporting both sides as drift.

## Acceptance criteria

- Rails::Engine's `railtie_routes_url_helpers` is ported onto the trails Engine
  (`packages/trailties/src/engine.ts`) as the real definition, delegating to
  `routes.urlHelpers(includePathHelpers)`.
- `routes-helpers.ts` keeps only the structural probe it needs; the
  `@noRailsEquivalent` tag on the interface member is deleted once the method
  has a genuine Rails counterpart in the manifest.
- `api:compare` pairs the ported name with `railtie_routes_url_helpers`;
  `api:extra` shows no new extras and no stale tags.
