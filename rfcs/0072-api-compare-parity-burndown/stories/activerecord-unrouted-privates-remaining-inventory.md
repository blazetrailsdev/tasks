## Context

Follow-up to `activerecord-unrouted-privates-drop-carried-arguments`, which
produced the inventory below and fixed the first cluster (check constraints).

That story swept `packages/activerecord/` for ported Rails privates that no
internal caller routes through — the same sweep PR #5025 ran over
`packages/arel/`. Method: cross `scripts/api-compare/call-mismatches-wide-exclude/activerecord/`
(its `<method> -> <private>` entries are exactly the "declared but not routed"
edges) against `scripts/api-compare/output/ts-api.json` (every ported TS method
plus its call-set), keep only privates that carry parameters and appear in
nobody's call-set, then confirm with a real grep for call sites.

Result: **95 candidates, 77 with no non-declaration call site at all.**

The first story shipped the check-constraint cluster:

- `SchemaStatements#checkConstraintOptions` was a hollow `{...options}` — it
  dropped its own `options[:name] ||= check_constraint_name(...)` body.
- `SchemaStatements#addCheckConstraint` did not route through it, and accepted
  `ifNotExists` while silently ignoring it (no `check_constraint_exists?` guard).
- `TableDefinition#newCheckConstraintDefinition` did not route through the
  adapter's `checkConstraintOptions`, reimplementing the `chk_rails_<sha>` name
  derivation in a private `_checkConstraintName` duplicate; `checkConstraint`
  in turn bypassed `newCheckConstraintDefinition`.

Everything else in the inventory is unexamined. Several entries are known
non-actionable and should be skipped rather than re-derived:

- `migration/join-table.ts#joinTableName` duplicating
  `model-schema.ts#deriveJoinTableName` is a **documented deliberate deviation**
  (import-graph TDZ; guarded by
  `scripts/test-deps/adapter-graph-import-tdz.test.ts`). Do not "fix" it.
- `connection-adapters/postgresql/quoting.ts#checkIntInRange` is an alias
  (`export const checkIntInRange = checkIntegerRange`) — routed, false positive.
- `relation/query-methods.ts#sanitizeOrderArguments` and
  `checkIfMethodHasArgumentsBang` are dead because `orderBang`/`reorderBang`
  inline the validation (`disallowRawSqlBang`) in a restructured body. Routing
  them is a real convergence but a much larger one — worth its own story.
- `encryption/key-generator.ts#generateRandomKey` sits on top of a pre-existing
  return-type deviation (trails returns base64, Rails returns raw bytes);
  routing `generateRandomHexKey` through it needs that settled first.

## Acceptance criteria

- Work the inventory in clusters, one PR per cluster, under the 500 LOC ceiling.
- For each argument-dropping case fixed, a test asserting the argument reaches
  the built node/SQL — not merely that the call returns the right class. That
  weak assertion is what let both the arel and the check-constraint cases sit
  undetected.
- Each new test verified to FAIL on the pre-fix implementation.
- Wide-baseline entries that converge are removed; baseline only shrinks.
  Re-run `API_COMPARE_FORCE=1 pnpm parity:api --wide-calls` before
  `pnpm parity:api:calls` (a stale artifact reports a false OK).
- Entries confirmed non-actionable get a `reason` on their wide-baseline entry
  explaining why, so the next sweep does not re-derive them.
