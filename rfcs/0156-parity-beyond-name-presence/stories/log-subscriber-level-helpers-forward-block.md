## Context

`ActiveSupport::LogSubscriber`'s private level helpers are generated by
`vendor/rails/v8.0.2/activesupport/lib/active_support/log_subscriber.rb:161-167`:

```ruby
%w(info debug warn error fatal unknown).each do |level|
  class_eval <<-METHOD, __FILE__, __LINE__ + 1
    def #{level}(progname = nil, &block)
      logger.#{level}(progname, &block) if logger
    end
  METHOD
end
```

trails' `packages/activesupport/src/log-subscriber.ts` `_info` / `_debug` / `_warn` /
`_error` / `_fatal` / `_unknown` take `progname` (renamed in trails#8990), but they drop
`&block`: the bodies are `l.info(progname)`, and they return `false` where Rails returns
`nil` when there is no logger (the `if logger` modifier). The block-param gate does not flag
them yet because the TS names are `_`-prefixed. trails#8990 surfaced this.

## Acceptance criteria

- Each helper takes a trailing `block` parameter and forwards it as `logger.<level>(progname, block)`.
- The no-logger arm returns `null`, as Rails' `if logger` modifier does, not `false`.
- `log-subscriber.test.ts` covers forwarding a block.
