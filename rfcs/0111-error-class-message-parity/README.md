# RFC 0111 — Error-class and message parity burndown

## Summary

CLAUDE.md's fidelity rule names errors explicitly: _"Same error class, same
message string, same raise site."_ The lint that enforces it already exists,
already runs at `"error"` severity, and already carries a numbered, only-shrink
debt ledger — **158 grandfathered files** in
`eslint/rails-error-parity-exclude.json`, plus 10 more in
`eslint/rails-error-parity-unported.json`. Nobody owns driving either to zero.

This RFC writes no tooling. It burns those two ledgers down, and folds in the
41 `0023-surfaced-deviations` stories that describe the same class of
divergence.

## Motivation

**Ruby has one `ArgumentError`. trails has at least three.**

- `packages/date/src/date.ts:205` — `export class ArgumentError extends Error`,
  which `Date::Error` extends and `Date.parse` raises.
- `packages/activemodel/src/attribute-assignment.ts:247` —
  `class ArgumentError extends globalThis.Error`, raised by
  `Type::DateTime#value_from_multiparameter_assignment`.
- `packages/activesupport/src/hash-utils.ts:13` — raised by `assertValidKeys`.

None is an instance of the others, so `instanceof` narrowing silently fails
across every package boundary **while `err.name === "ArgumentError"` still
passes**. A test that checks the name cannot see the bug. The same shape repeats
for `NoMethodError` and `TypeError`.

Elsewhere the divergence is a bare throw where Rails names a class:

| trails                                                                 | Rails                                                       |
| ---------------------------------------------------------------------- | ----------------------------------------------------------- |
| `throw new Error("You cannot call create unless the parent is saved")` | `RecordNotSaved` (fixed since; see below)                   |
| `throw new ActiveRecordError("Cannot build type condition …")`         | no raise at all — `inheritance.rb:322-327` has no nil check |
| `verifyReadonlyAttribute` throws `ReadonlyAttributeError`              | `ActiveRecordError` (`persistence.rb:945-947`)              |

### The gate is already built

`eslint/rails-error-parity.mjs` is wired at `eslint.config.mjs:376`, scoped over
`packages/{activerecord,activemodel,activesupport}/src/**/*.ts`. It does two
things:

1. every error class in the generated manifest `eslint/rails-error-classes.json`
   must be mirrored in the file its Rails source lives in; and
2. bare `throw new Error(` (and `TypeError` / `globalThis.Error`) is banned in
   Rails-mirroring source.

The manifest is regenerated by `scripts/build-rails-error-manifest.ts`, which
regex-scans vendored Rails for error declarations and grows the set to a
fixpoint. The rule's own header already states the contract: the exclude list
**only shrinks**. A companion, `eslint/rails-error-parity-unported.test.mjs`,
closes the rule's file-driven blind spot — a manifest class whose Rails home
file is entirely unported never gets linted, because there is no file to visit
— by walking the manifest directly and requiring each such class to be listed
in `rails-error-parity-unported.json` with a reason, on the same only-shrink
contract.

So the metric, the enforcement and the direction all exist. What is missing is
someone whose job is the number.

### It mostly free-rides on work already scheduled

**96 of the 158 excluded files — 60% — are already named by at least one open
`0023-surfaced-deviations` draft**, and 326 drafts name an excluded file.
Whoever claims one of those stories is already in the file with the Rails
counterpart open. Clearing that file's error-parity row is a drive-by, not a
separate errand.

That is the core bet of this RFC: most of the 158 does not need dedicated
stories, it needs a standing expectation.

## Design

### Three kinds of row, three treatments

1. **Duplicate class definitions.** One shared class per Ruby error, exported
   once, imported everywhere. This is the only part with a cross-package
   dependency graph, so it goes first — every later row that raises
   `ArgumentError` needs the single class to already exist.
2. **Bare `throw new Error`.** Replace with the class Rails raises at that
   site, message string verbatim. Where Rails does not raise at all, the
   convergence is deleting the throw, not renaming it — see
   `converge-type-condition-invented-null-column-error`, where the guard defends
   a state `finder_needs_type_condition?` makes unreachable.
3. **Message strings.** Same text, same interpolation, same raise site. This is
   the tail and the cheapest per row.

### Ledger discipline

The two baselines are only-shrink by construction. On converging a file, delete
its row by hand — never regenerate the list, which would bury the one row you
retired in an unreviewable diff. A row is retired when the file passes the rule,
not when a story closes.

### Relationship to 0023

The 41 matching `0023-surfaced-deviations` stories move here on adoption,
**carrying their Rails `file:line` citations verbatim**. Those citations are the
expensive part of that backlog. The 2026-08-18 triage pass found three stories
pointing at a deleted file, a retired tool, and a convergence target that had
moved — re-homing is exactly the moment that damage gets done.

## Non-goals

- **Widening the rule's package scope.** It covers activerecord, activemodel and
  activesupport today. `arel`, `date`, `rack` and `i18n` appear in the story set
  and are declared in `packages:` so re-homed stories validate, but extending
  the lint's scope is a separate decision with its own noise budget.
- **Error _hierarchy_ redesign.** Where Rails' own hierarchy is awkward, we
  mirror it anyway. This RFC converges on Rails, it does not improve on it.
- **Rewriting `build-rails-error-manifest.ts`.** The manifest is regex-based and
  admits that in its header. If it proves to under-report, that is a story, not
  a reason to hold this RFC.

## Alternatives considered

- **Fold into `0082-ruby-ts-idiom-conversion-classes`.** That RFC is the right
  conceptual home — a bare `throw new Error` is a Ruby-idiom mistranslation. But
  0082 is `postponed` with 15 drafts and no gate, and this class is the one with
  a live ratchet. Reviving 0082 to carry it would bury a finishable campaign
  inside a stalled one.
- **Leave it in 0023.** The ledger has sat at 158 without an owner precisely
  because 0023 has no metric. A register with 676 drafts cannot report progress
  on 158 files.
- **Gate-first: raise severity and delete the exclude in one sweep.** Turns ~158
  files red at once with no landing path. Rejected on review-bandwidth grounds.

## Rollout

Phases are ordered by dependency, not by size. Story IDs are assigned when the
RFC moves to `active` and the 0023 stories re-home.

1. **Phase 1 — collapse the duplicate classes.** One `ArgumentError`, one
   `NoMethodError`, one `TypeError`, each exported from the package that owns
   the Ruby original. Everything else depends on this.
2. **Phase 2 — retire the `-unported.json` rows** that are no longer unported.
   Pure ledger hygiene; the companion test already enforces the direction.
3. **Phase 3 — the 96 overlapping files**, as a standing drive-by rule on every
   0023 claim in those files. Tracked by exclude-row count, not story count.
4. **Phase 4 — the remaining 62 files** with no 0023 story, as dedicated
   stories. The long tail, and the only phase needing its own scheduling.

## Verification

- `eslint/rails-error-parity-exclude.json` reaches **0 entries** (from 158).
- `eslint/rails-error-parity-unported.json` reaches **0 entries** (from 10), or
  every surviving entry names a Rails file that is still genuinely unported.
- No `ArgumentError`, `NoMethodError` or `TypeError` class is declared in more
  than one package.
- `pnpm lint` green with the rule at `"error"` and no exclude file present.

Phase 3 additionally reports **exclude rows retired per phase**, so the drive-by
mechanism can be judged on evidence rather than assumed to work.

## Open questions

1. **Does the drive-by expectation actually hold?** Phase 3 assumes an agent
   claiming an unrelated 0023 story in an excluded file will also clear the
   error row. If Phase 3 retires fewer than ~30 of its 96 rows in its first
   pass, convert the remainder to dedicated stories and say so — do not keep
   asserting a mechanism the data contradicts. **Recommendation:** adopt with
   this tripwire written into Phase 3.
2. **Should the rule's scope widen to `arel` / `date` / `rack` / `i18n`?**
   14 of the 41 stories touch them. **Recommendation:** defer to a follow-up
   story once the in-scope ledger is under 40, so the noise is measured against
   a clean baseline rather than a dirty one.
3. **`ReadonlyAttributeError` vs `ActiveRecordError`.** `verify_readonly_attribute`
   raises the generic class in Rails (`persistence.rb:945-947`); trails raises a
   specific one. Converging loses information a caller might rely on.
   **Recommendation:** converge, per "same error class" — but confirm no trails
   test asserts the narrow class first.
