## Context

`vendor/rails/activemodel/lib/active_model/attribute_methods.rb` is 236 code
lines; `packages/activemodel/src/attribute-methods.ts` is 510. 232 lines map
onto Rails members; **124 do not**:

- Copy-on-first-write helpers: `ensureOwnPatterns` (`:261`, `:274`, `:286`,
  `:735`) and `ensureOwnAliases` (`:295`, `:741`) — six call sites, ~36 code
  lines. Rails needs none of them: `attribute_method_patterns` and
  `attribute_aliases` are `class_attribute`s (`attribute_methods.rb:72,74`),
  which give per-subclass copy semantics for free.
  `packages/activesupport` ports `class_attribute`; use it.
- `defineDirtyAttributeMethods` (`:309`, `:765` — 38 lines). `dirty.rb` has no
  such method; Rails' dirty methods are generated by the same
  `define_attribute_methods` pass through
  `attribute_method_patterns`/`define_attribute_method` and the suffix patterns
  `Dirty` registers (`dirty.rb:135-148`). This is a parallel generator.
- `resolveAliasName` (`:814`) and `resolveAliasNameIn` (`:846`) — Rails has one
  `resolve_attribute_name` (`attribute_methods.rb:396-398`), which the file
  already ports at `:493`. Three spellings of one thing.
- `isDefinedByAClassBody` (`:676`, 12 lines) and `extractParameters` (`:654`).

`pnpm parity:api:extra --package activemodel` scores the file 5 novel / 2
moved (`attrName`, `defineDirtyAttributeMethods`, `method_missing_target`,
`prototype`, `resolveAliasName` novel). `activemodel/attribute-methods.json`
holds 7 baseline rows, joint-largest in the package.

Note CLAUDE.md's ratified repo-wide rule "Generated attribute readers are
properties (`define_method_attribute`)" — the reader-as-property decision and
the "must not shadow an inherited method" guard are settled and are **not** to
be re-litigated here. This story converges the _pattern/alias bookkeeping_
around them.

## The mixin idiom to use (RFC finding F0)

All three mechanisms this story needs are already ported and exported, and
activemodel currently uses none of them — see this RFC's F0. Do not hand-roll a
fourth spelling:

- **`classAttribute()`** — `packages/activesupport/src/class-attribute.ts:70`,
  exported from the package index (`:387`). Its contract is exactly Rails'
  `class_attribute`: _"reads walk the constructor chain; writes are local to the
  class"_. It has **zero** callers in activemodel today.
- **`extend()` / `Extended<>`** — `packages/activesupport/src/include.ts:335`.
  The TS spelling of `extend SomeModule`, i.e. the `ClassMethods` half of a
  Concern. **Zero** callers in activemodel; 65 in activerecord.
- **`include()` / `Included<>`** — `include.ts:184`, plus the symbol-keyed
  `[included]` / `[extended]` hooks fired at `include.ts:193,272,371`, which are
  the TS spelling of an `included do` block. The hooks are keyed by
  `Symbol.for(...)`, so they never surface to `parity:api:extra` and do not
  collide with the `SKIP_GROUPS` ban on a string-named `included` member
  (`scripts/parity/conventions.ts:444`, `tsMirrorIsDrift: true`). CLAUDE.md's
  "Module mixins" section still says these hooks have no TS equivalent; that is
  stale for `included`/`extended` and true only for `inherited`.

## Acceptance criteria

- `ensureOwnPatterns` / `ensureOwnAliases` are replaced by
  `classAttribute()` from `@blazetrails/activesupport`, matching
  `attribute_methods.rb:71-72`'s
  `class_attribute :attribute_aliases, instance_writer: false, default: {}`
  and `:attribute_method_patterns`. All six call sites go.
- No new copy-on-first-write helper is introduced under any name; this story
  removes two of the package's five spellings of that mechanism (F0).
- One alias-resolution method survives, at the Rails name
  `resolveAttributeName`.
- `defineDirtyAttributeMethods` is folded into the Rails generation path via
  the suffix patterns `dirty.rb:135-148` registers, or the PR states precisely
  which Rails mechanism it stands in for.
- `pnpm parity:api:extra --package activemodel` shows `attribute-methods.ts` at
  ≤ 1 novel.
- `activemodel/attribute-methods.json`'s 7 rows shrink; converged rows
  hand-deleted then tightened.
- `pnpm lint --fix` after `pnpm parity:api`.
- Parity deltas non-negative for activemodel **and** activerecord.
