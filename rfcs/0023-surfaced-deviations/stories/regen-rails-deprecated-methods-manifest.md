## Context

`eslint/rails-deprecated-methods.json` is machine-generated by
`scripts/build-rails-privates-manifest.ts` and regenerated in place by
`eslint --fix` (see `eslint/rails-deprecated-jsdoc.mjs:15-16`). Its
`packages/activesupport/src/core-ext/benchmark.ts` entry (`ms`) names a file that
no longer exists under `core-ext/`, so the entry is stale and enforces nothing.

Found while reviewing PR #5696: lint-staged's `eslint --fix` rewrote the manifest
mid-commit and the trimmed result rode along with `git add -A` (it also dropped
the _live_ `connection-adapters/mysql/schema-definitions.ts` entry, which was
restored in e75db3f73). The regen is therefore correct about `benchmark.ts` and
wrong about `schema-definitions.ts` — worth understanding before trusting a
regen, since the drop of a live entry silently removes enforcement.

## Acceptance criteria

- The stale `benchmark.ts` entry is removed by a proper regen
  (`scripts/build-rails-privates-manifest.ts`), not a hand-edit.
- The `schema-definitions.ts` entry survives the regen — or, if the generator
  legitimately no longer sees it, why is established and recorded.
- If `eslint --fix` regenerating a committed manifest from build state is itself
  the hazard (it is how PR #5696 nearly shipped a silent enforcement drop), note
  whether the generation belongs behind an explicit script instead.
