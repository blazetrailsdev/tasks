## Context

Surfaced by trails#8001, which deleted the PostgreSQL/MySQL `TableDefinition.defineColumnMethods`
overrides in favour of the inherited one. That inherited body
(`packages/activerecord/src/connection-adapters/abstract/schema-definitions.ts`,
`TableDefinition.defineColumnMethods`) diverges from Rails'
`ColumnMethods.define_column_methods` (`activerecord/lib/active_record/connection_adapters/abstract/schema_definitions.rb:332-341`):

- Rails `module_eval`s onto the **receiver** (the including module/class), so
  `PostgreSQL::ColumnMethods` (`postgresql/schema_definitions.rb:185`) and
  `MySQL::ColumnMethods` (`mysql/schema_definitions.rb:46`) define their methods on themselves.
  Trails always writes to the abstract `TableDefinition.prototype`, ignoring `this`, and skips a name
  already `in` the prototype. Rails redefines it unconditionally.
- Rails' generated body is `raise ArgumentError, "Missing column name(s) for #{column_type}" if names.empty?`
  then `names.each { |name| column(name, :#{column_type}, **options) }`. Trails routes through an
  invented `definedColumn(type, args)` helper.
- The method is `private` in Rails (`:342`), and trails has no caller. Rails' PG/MySQL `included do`
  blocks call it, while trails writes each adapter type as an explicit method.

## Acceptance criteria

- `defineColumnMethods` defines on `this.prototype` (the receiver), unconditionally, with the Rails body
  (`names.length === 0` -> `ArgumentError("Missing column name(s) for <type>")`, then `this.column(name, type, options)` per name).
- Either the abstract, PG and MySQL column method lists are generated by calling it (matching
  `schema_definitions.rb:324`, `postgresql/schema_definitions.rb:185` and `mysql/schema_definitions.rb:46`),
  or the story records why the explicit typed methods must stay.
- `definedColumn` is removed if nothing else needs it.
- `pnpm parity:api:extra:gate` and `pnpm parity:api:calls` stay green.
