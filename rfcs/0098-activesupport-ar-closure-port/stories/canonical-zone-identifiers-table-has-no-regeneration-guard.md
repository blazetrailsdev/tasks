## Context

PR #6276 added `CANONICAL_ZONE_IDENTIFIERS` to
`packages/activesupport/src/values/time-zone.ts` — 121 tzdata backward-link
pairs standing in for the canonicalization
`TZInfo::Country#zone_identifiers` does for free
(`activesupport/lib/active_support/values/time_zone.rb:275`). The runtime
exposes no link table (`Intl.DateTimeFormat#resolvedOptions().timeZone` echoes
link names back unchanged on node 24), so the pairs are carried as data.

The table was generated by diffing `TZInfo::Country.get(code).zone_identifiers`
against `new Intl.Locale("und-"+code).getTimeZones()` for all 249 codes and
resolving each intl-only identifier to its canonical target by offset signature
over 1900-2035. That procedure exists only in the PR's scratch work — **nothing
in the tree regenerates or verifies it.**

Two ways it silently rots:

1. **tzdata moves.** A new release retires a zone into a link (as it did for
   `Europe/Kiev` → `Europe/Kyiv`, `Asia/Calcutta` → `Asia/Kolkata`) and the
   table misses the new pair. `countryZones` then answers an IANA-named zone
   where Rails answers a MAPPING name — exactly the bug #6276 fixed, resurfacing
   silently.
2. **ICU moves.** A node upgrade may start canonicalizing on its own, at which
   point entries become dead weight rather than wrong.

Neither shows up in CI: the two tests #6276 added pin `va` and `ua` only, and
Rails' four `test_country_zones*` cases are all ZONE-backed.

## Converged shape

Commit the generator as a script beside the other parity tooling and add a test
that regenerates the table in-process and asserts it equals the committed one,
skipped when `ruby`/`tzinfo` is unavailable so it cannot red CI on a runner
without them. That makes a tzdata bump a visible, reviewable diff instead of a
silent divergence.

Cheaper alternative if the generator is judged too heavy: a test that walks all
249 codes and asserts every identifier in the table is still reported by
`getTimeZones` for some country, catching dead entries but not missing ones.

## Acceptance criteria

- [ ] The table's provenance is reproducible from a committed script, not from
      a PR's scratch work.
- [ ] A tzdata/ICU move that invalidates the table fails a test rather than
      silently changing `countryZones`.
- [ ] The check degrades to a skip where `ruby`/`tzinfo` is absent.
