# RFC — Rails 8.0.5.2 burn-down

## Summary

The Rails source of truth moved from `v8.0.2` to `v8.0.5.2` under the
`rails-8-0-5-1-upgrade-workflow` RFC, with every drifted or removed body pin
and every changed test parked in the bump ledger
(`scripts/parity/bump-ledger/rails.json`, `rails.tests.json` in trails). This
RFC holds the stories that empty that ledger, one per package or subsystem.

## Motivation

A ledger row is a body the port has not re-verified against the new Rails.
Until each is re-read, re-ported where it changed, and re-pinned, the gates
skip it, and the tests upstream added in the bump are unported.

## Design

Every story here is generated, not hand-written, by
`scripts/parity/bump-dry-run/generate-stories.ts` in trails, run as

```sh
pnpm parity:bump:stories --source rails --from v8.0.2 --to v8.0.5.2 \
  --from-tests <rails-tests.json extracted at v8.0.2> \
  --rfc 0000-rails-8-0-5-2-burn-down --out rfcs/0000-rails-8-0-5-2-burn-down/stories \
  --config scripts/parity/bump-ledger/rails.stories.json
```

Each story lists, per Ruby file it owns, the `git diff --no-index` between
the two vendored versions, the TS file, its ledger rows, and the added,
removed and changed upstream tests of its test files. Its acceptance criteria
end in a `body-pins.ts --pin` per Ruby file, no ledger row left in its files,
and every added test ported or recorded as not ported with its reason.

A package over 15 Ruby files is split along subsystem directories
(`rails.stories.json`), never below one file. Stories depend on every story of
the package before them, in the order arel, activemodel, activesupport,
activerecord, actionpack, actionview, actioncable, activejob, actionmailer,
activestorage, actionmailbox, actiontext, trailties. The actionview story
owning `sanitize_helper.rb` and `text_helper.rb` also depends on
`bump-rails-html-sanitizer-to-v1-7-2`.

## Non-goals

- Rails 8.1: its own bump, generated by the same script.
- Hand-editing the stories: rerun the generator against the current ledger.
