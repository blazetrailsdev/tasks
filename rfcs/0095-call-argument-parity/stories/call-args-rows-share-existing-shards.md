## Context

**Decision change (Dean, 2026-08-10): call-argument rows live in the existing
per-file baseline shards, not in a new parallel tree.**

RFC 0095 `## Rollout` (README:190) currently specifies a second baseline tree,
`scripts/api-compare/call-mismatches-args-exclude/`, on the grounds that
`call-mismatches-exclude`'s key has no argument component and that RFC 0084
measures that tree's row count as the debt metric, so a second dimension would
corrupt the measurement.

The measurement concern is real but does not require a second tree: it requires
a discriminator on the row. Two parallel trees over the same
`package + tsFile` sharding means every burndown PR that touches a file's
arguments and its call set edits two JSON files in two directories for the same
source file, and every agent rebasing across both trees eats two conflict
surfaces instead of one.

Target shape — one shard file per source file, as today:

    scripts/api-compare/call-mismatches-exclude/<package>/<path>.json

Rows gain an optional `kind` discriminator:

- absent (or `"calls"`) — an RFC 0047/0084 call-set row. Existing rows are
  untouched; no migration of the ~current population, and the seeded `reason`
  strings stay exactly as they are.
- `"args"` — a call-argument row, carrying the additional `rubyArgs` key
  component alongside `package + tsFile + rubyName + call`.

Each gate filters the shard to its own `kind`, so RFC 0084's row count remains
exactly the count of call-set rows and the call-argument burndown count is
independently derivable. Neither number moves because of the other dimension.

Anchors:

- `scripts/api-compare/call-mismatch-baseline.ts:63` — `CallMismatchKey`
  (`package`, `tsFile`, `rubyName`, `call`); `:70` `ExcludeEntry` adds `reason`.
  This is where `kind` and `rubyArgs` are added, both optional so every existing
  shard file parses unchanged.
- `scripts/api-compare/call-mismatches-exclude/activerecord/tasks/postgresql-database-tasks.json`
  — representative shard; rows are a flat JSON array.
- `scripts/api-compare/report-call-args.ts:23` — the advisory artifact is
  `output/call-arg-mismatches.json`, gitignored (`.gitignore:5`) and
  regenerated by `compare.ts --calls`. It is NOT affected by this story; only
  the committed baseline shape changes.
- `scripts/api-compare/baseline-json.ts` — `serializeBaseline`, which must
  remain the only writer (json.dumps escapes em-dashes and reds Unit Tests).

`call-args-ratchet-and-ci-step` (PR #6334) is in flight against the old shape.
Whichever of the two lands second absorbs the other's delta; this story owns
the final shape either way.

## Acceptance criteria

1. `scripts/api-compare/call-mismatches-args-exclude/` does not exist. Call-arg
   rows are written into the existing `call-mismatches-exclude/<package>/<path>.json`
   shards.
2. `ExcludeEntry` gains optional `kind: "calls" | "args"` and `rubyArgs`; both
   optional so every existing shard file loads with no edit and no reseed.
3. The call-set gate (`lint-call-mismatches.ts`) filters to `kind` absent or
   `"calls"`, and its reported row count is unchanged from before this story —
   assert the exact pre-change number in a test.
4. The call-arg gate filters to `kind === "args"` and keys on
   `package + tsFile + rubyName + call + rubyArgs`.
5. Both gates keep only-shrink semantics and the stale-row arm independently:
   an args row going stale must not red the call-set gate, and vice versa.
6. Rows within a shard are written in one canonical order covering both kinds,
   via `serializeBaseline` — never a hand-written or `--write` reseed.
7. `pnpm parity:api:calls` and the call-arg gate are both green on `main` after
   the change.
8. RFC 0095 `## Rollout` and `call-args-baseline-seed` are updated to the shared
   -shard shape; no doc still names `call-mismatches-args-exclude`.
