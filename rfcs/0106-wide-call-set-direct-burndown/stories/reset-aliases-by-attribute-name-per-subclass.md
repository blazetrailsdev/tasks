# Reset `aliases_by_attribute_name` per subclass, mirroring Rails' `inherited` hook

## Context

Split out of PR #6838. That PR converged `generate_alias_attributes` onto
Rails' registry and grouping — it now walks
`aliasesByAttributeName` as `old_name => [new_names]`
(`activerecord/lib/active_record/attribute_methods.rb:132-137`) instead of the
inverse `attribute_aliases`. What it did NOT change is the registry's
inheritance semantics, which are still trails-specific.

**Rails** keeps `aliases_by_attribute_name` as a plain per-class ivar
(`activemodel/lib/active_model/attribute_methods.rb:382-384`):

    def aliases_by_attribute_name # :nodoc:
      @aliases_by_attribute_name ||= Hash.new { |h, k| h[k] = [] }
    end

and its `inherited` hook RESETS it on every subclass
(`activemodel/lib/active_model/attribute_methods.rb:387-394`):

    def inherited(base) # :nodoc:
      super
      base.class_eval do
        @attribute_method_patterns_cache = nil
        @aliases_by_attribute_name = nil
        @generated_attribute_methods = nil
      end
    end

So a subclass starts EMPTY: `Sub.generate_alias_attributes` generates only the
aliases declared on `Sub`, because the parent's were already generated by the
`superclass.generate_alias_attributes` cascade at
`activerecord/lib/active_record/attribute_methods.rb:128`.

**trails** (`packages/activemodel/src/attribute-methods.ts:492-501`)
copy-on-writes the parent's entries instead:

    export function aliasesByAttributeName(host) {
      if (!Object.prototype.hasOwnProperty.call(host, "_aliasesByAttributeName")) {
        const parent = host._aliasesByAttributeName;
        const copy = new Map();
        if (parent) for (const [k, v] of parent) copy.set(k, [...v]);
        host._aliasesByAttributeName = copy;
      }
      return host._aliasesByAttributeName;
    }

Consequence: a subclass re-generates every INHERITED alias, with
`override: true`, taking its own descriptor where Rails leaves it inheriting the
parent's.

## Converged shape

`aliasesByAttributeName` starts empty for a class with no OWN
`_aliasesByAttributeName`, rather than copying the parent's:

    const copy = new Map<string, string[]>();
    host._aliasesByAttributeName = copy;

JS has no `inherited` hook (CLAUDE.md, "Module mixins"), so the own-property
check IS the port of the reset — the copy is the part to delete, not the guard.

## Watch out

- `packages/activemodel/src/attribute-methods.ts:317` (`aliasAttribute`) and
  `:380` (`defineAttributeMethod`) also read this registry; check both against
  Rails before changing the semantics.
- `attribute-methods.trails.test.ts > an inherited generated attribute method
does not suppress the subclass's own generation` asserts the CURRENT
  behaviour (the alias inherited from `Middle` is regenerated on `Leaf`).
  Re-derive it against Rails — with the reset, `Leaf`'s registry is empty. Do
  not change the test NAME.
- This is cross-package: ActiveModel owns the registry, ActiveRecord consumes
  it.
