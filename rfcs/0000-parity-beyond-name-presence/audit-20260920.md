# Audit: what tooling would have caught RFC 0155's 180 port bugs

> **Corrections after review, 2026-09-20.** Two of this audit's proposals were narrowed when the RFC was written. Proposal 1 said to un-skip the whole global name group. Only the names that translate directly are un-skipped (`inspect`, the `dup` family, `encode_with` / `init_with`, the explicit conversions). Names whose JS form is a different mechanism get a decision story, and names with no JS hook stay skipped. The section "The call gates have the same hole" implied `public_send` should become a scored call name. It should not: `send` and `public_send` differ only in visibility, and the faithful port is a computed-member assignment with no callee. Proposal 3, the MRI differential harness, was declined by the owner and no story builds it. The README and stories carry the corrected shape.

## Summary

All 180 story bodies in `rfcs/0155-assertion-surfaced-port-bugs/stories/` were read and sorted by defect shape. `parity:api` was built and run on `4e7c35e36b`, and its artifacts were queried directly.

Two findings lead.

1. **`parity:api` measures name presence, and its "100%" is 100% of a filtered list.** In activerecord, 83.1% of Rails' method definitions get a row of their own. In activesupport it is 68.6%. The rest are removed by name, by file, or by collapsing same-named methods. Of the 27 "method is simply not ported" stories, **one** shows up as missing in `parity:api` output.
2. **The premise "every gate reads ~100%" is only true for arel, activemodel and activerecord.** activesupport reads 91.5% with 171 reported misses, and 54 of the 180 stories cite activesupport or `packages/date` source. Some of what 0155 is rediscovering by hand is already printed by the tool and nobody is working that list.

About 85 of 180 (47%) are reachable by static or differential tooling. About 61 (34%) are not, and the report says which.

### The five mechanisms

1. **Global skip by name.** `SKIP_GROUPS[0]` (`scripts/parity/conventions.ts:455-498`) lists `dup`, `inspect`, `pretty_print`, `respond_to?`, `respond_to_missing?`, `method_missing`, `is_a?`, `initialize_dup`, `encode_with`, `init_with`, `to_a`, `to_h`, `to_i` and more. `rubyMethodToTs` returns `null` for them (`conventions.ts:1484`), and `dedupeRubyMethodInto` drops a null-mapped method before it reaches the expected set (`compare.ts:2920`). Top hits in AR, AM and AS: `inspect` 29, `hash` 20, `eql?` 19, `method_missing` 18, `initialize_dup` 16, `encode_with` 14, `init_with` 11, `respond_to_missing?` 11. **Every `inspect` in Rails is outside the denominator**, which is the whole RENDER group.
2. **Same-file, same-name collapse.** The expected set is keyed by Ruby method name per file (`compare.ts:2922-2933`, doc at `:2768-2770`). A class-level and an instance-level method of one name are one row. 127 AR definitions collapse across the class/instance line. `ActiveRecord::AttributeMethods::ClassMethods#attribute_method?` is unported and scores matched, because the file also has an instance `isAttributeMethod`.
3. **Name-only matching, any member kind.** A predicate `foo?` is satisfied by `isFoo`, `foo`, or `fooQ` (`conventions.ts:1469-1478`). `ConnectionPool#active_connection?` scores matched against the getter `get activeConnection(): DatabaseAdapter | null` (`connection-pool.ts:364`). A match can also come from a TS includer or a parent class (`compare.ts:4704-4723`).
4. **Excluded files and rowless files.** `scripts/parity/unported-files/` removes 293 AR and 229 AS definitions. `migration/compatibility.rb` is one, and two 0155 stories are about it. A further 104 AS definitions sit in files with no row at all, because every member is scoped-skipped or the class is Ruby-only (`compare.ts:2921`). `multibyte/chars.rb` (24 definitions) is one, and `assertions-activesupport-multibyte-chars-port` asks to port it. `test_order` is scoped-skipped with the reason "vitest owns ordering" (`conventions.ts:1070-1088`), and `activesupport-test-case-has-no-test-order` asks to port it. **Two 0155 stories contradict a recorded skip reason, and nothing notices.** Each needs a decision before anyone works it.
5. **Stdlib includes are not flattened.** `flattenIncludedMethodInfos` silently skips modules outside the package, naming `Comparable` and `Enumerable` (`compare.ts:2633-2634`). `ActiveModel::Errors` includes `Enumerable`; `map`, `first` and block-form `any?` are never expected.

Hypotheses from the brief that did **not** hold: the Ruby extractor does emit `attr_*`, `delegate`, `def_delegators`, `alias_method`, `define_method`, `class_attribute` and `mattr_*` (`extract-ruby-api.rb:909-939`). `@internal` was not implicated in any of the 27.

### The call gates have the same hole

`update-attribute-uses-public-send-setter` is a wrong call: Rails calls `public_send("#{name}=")`, trails calls `writeAttribute`. The skeleton artifact records exactly that (`ruby: [..., "ref:public_send", ...]`, `ts: [..., "ref:writeAttribute", ...]`), yet `call-mismatches.json` has no row. `public_send` is a SKIP name, so it maps to no TS candidate, and `significantMissingCalls` (`compare.ts:609`) suppresses a Ruby call that maps to no ported TS method. `send`, `respond_to?`, `is_a?` and `inspect` go the same way. `NO_JS_CALL_FORM` (`compare.ts:312-319`) additionally drops `to_s`, `present?`, `blank?`.

So the three call names that most often carry a fidelity decision (`respond_to?`, `inspect`, `public_send`) are invisible to both the surface gate and the call gate.

## Ranked proposals

### 1. Audit the denominator: split SKIP into "unscoreable" and "unported", and kind-check matches

- **What.** (a) Print the own-row ratio beside the percentage. (b) Replace the global name skip with per-definition accounting: a Ruby file that defines `inspect`, `initialize_dup`, `is_a?`, `respond_to_missing?` expects a TS counterpart in that file, using the spellings `rubyMethodToTsIgnoringSkip` (`conventions.ts:1509`) already produces for extra-surface. (c) Key the expected set on (level, name) so class and instance do not collapse. (d) Reject a predicate matched by a non-boolean getter. (e) Flatten `Enumerable` and `Comparable` into an expected list when the class defines `each` or `<=>`.
- **Catches.** 11 of the 27 UNPORTED directly (the skip-name 6, false-match 4, stdlib 1). It also turns RENDER from invisible to listed: 29 `inspect` definitions become rows, which covers `base-inspect-returns-unqualified-name`, `aes256-gcm-inspect-not-rails-format`, `hash-config-inspect-omits-ruby-class-path`, `pool-inspect-…`, `abstract-adapter-inspect-…`, `relation-pretty-print-record-format` as "exists but unverified" at minimum. Honest count: **10 caught, 6 more made visible.**
- **Cost.** Medium. About 300 to 500 LOC in `compare.ts` and `conventions.ts`, plus a burndown, because AR will drop from 100% to roughly 97% the day it lands. That drop is the finding, stated as a number.
- **Fails by** re-flagging members that are truly unportable (`hash`, `object_id`, `freeze`). Those need a per-name `PERMANENT` list, which is what the group's `reason` already is. Keep them skipped; un-skip only names trails demonstrably ports somewhere.
- **Prior art.** RFC `0110-parity-skip-register-correctness` (`audit-remaining-scoped-skip-groups-for-ported-surface`, done) audited SCOPED groups only. `0072/activesupport-closure-skip-groups-triage` (done) triaged AS names. `compare-drops-nested-class-methods-from-coverage-denominator` (done) fixed one earlier denominator hole and is cited in `compare.ts:2763-2768`. Nobody has audited the global group or the name-collapse. Belongs to RFC 0126 by its charter: it changes a verdict on today's `main`.

### 2. Work activesupport's existing miss list before building anything

- **What.** No tool. `parity:api` already lists 171 activesupport misses across 46 files, including `test_case.rb` (16), `testing/stream.rb` (3), `testing/time_helpers.rb` (6), `callbacks.rb` (25).
- **Catches.** `port-activesupport-testing-stream-capture` outright, and it is the cheapest route to the AS half of UNPORTED and ARM. 54 of 180 stories cite AS or date source.
- **Cost.** Zero tooling. A scheduling decision.
- **Prior art.** RFC `0072-api-compare-parity-burndown`.

### 3. MRI differential harness for pure functions (`inspect`, messages, casts, numerics)

- **What.** A fixture is a Ruby expression and a TS expression. Ruby runs under `ruby -I vendor/rails/activesupport/lib -I vendor/rails/activemodel/lib`, with no bundler and no database. Both sides print `[class, inspect, raised-class, message]` as JSON and a diff gates. This is `scripts/parity/pipeline/` with a third `--type`: that pipeline already runs Rails and trails side by side over 206 fixtures and diffs the output (`run.ts:1-24`), but compares only `to_sql` text (`canonical/query-types.ts:7-8`) and schema dumps.
- **Tractable for.** ActiveSupport core extensions, `Duration`, `TimeWithZone`, `ActiveModel::Type::*#cast` and `#serialize`, `Errors`, `Error`, HWIA, inflections, `to_sentence`, pragma and deferrable validators. Two stories already verified their claim this way by hand (`decimal-cast-answers-one-for-a-boolean`, `duration-divide-by-integer-keeps-float-parts`).
- **Catches.** `decimal-cast-…`, `duration-divide-…`, `to-sentence-…`, `uuid-cast-array-stringification`, `activemodel-error-type-default-swallows-explicit-nil`, `attribute-assignment-argument-error-names-js-number-not-integer`, `serialization-type-mismatch-…`, `quote-error-message-…`, `duration-since-rejects-a-datetime-receiver`, `duration-sum-guard-…`, `date-cast-value-middle-arm-…`, `time-zone-converter-cast-missing-infinite-arm`, `activesupport-time-sec-fraction-rational`, `activemodel-errors-frozen-empty-array-raises-typeerror`, `deprecation-proxies-do-not-require-a-deprecator`, `testing-deprecation-helpers-…`, `range-step-…`, `enumerable-sum-…`. **About 18 to 22**, but only if someone writes the input. The harness finds nothing by itself.
- **The real lever is input generation.** Drive each `Type#cast` with a fixed adversarial value table (`nil`, `true`, `""`, `" "`, `0`, `1.5`, a Symbol, an Array of one, a Hash, a `Time`, a `DateTime`, a `TimeWithZone`, `Float::INFINITY`). That table alone hits DUCK, IDIOM and RENDER in the type layer without a human choosing cases.
- **Not tractable for.** Anything needing a connection, fixtures, or a Rails boot: all of QUERY, DRIVER, most of LOGIC, association behaviour. AR's `inspect` methods need a model, so they need the existing pipeline's Gemfile path instead.
- **Cost.** Medium. About 400 LOC of harness, reusing pipeline plumbing, then fixtures. CI already has Ruby for the pipeline job (`ci.yml:759`).
- **Fails by** async on the TS side, locale and time zone drift (freeze both, as the pipeline does with `PARITY_FROZEN_AT`), and `inspect` of objects with addresses.
- **Prior art.** `scripts/parity/pipeline/` (SQL and schema only). RFC 0086's README says codegen input is "not a correctness oracle; semantic verification stays with the tests" (`README.md:60`), which is a scope statement, not a rejection. `vendor-ruby-mri-source` and `ruby-compat-mri-citation-lint` cite MRI but never execute it. No story proposes executing MRI. **None found for this shape.**

### 4. Two lints: string rendering and closed `instanceof` guards

- **4a. Rendering lint.** Flag `JSON.stringify(`, `String(x)`, `.constructor.name` and `.constructor?.name` inside a template literal or an error constructor argument in a Rails-matched file. The Rails side is `inspect`, `.class`, `.class.name`. Catches `deferrable-error-message-symbol-inspect`, `deferrable-error-message-use-inspect`, `sqlite-pragma-error-parity`, `quote-error-message-uses-js-constructor-name`, `serialization-type-mismatch-…`, `attribute-assignment-argument-error-…`, `uuid-cast-array-stringification`, `hash-config-inspect-…`, `ar-base-abstract-class-message-…`: **9**. Cost: small, one ESLint rule. Fails by flagging genuine JSON output, so scope it to throw sites and `inspect` bodies. Prior art: point stories only (`check-constraint-raise-message-uses-json-stringify-not-ruby-hash-inspect`, `paths-and-attribute-set-inspect-messages-use-json-stringify`, `batches-order-inspect-hand-rolls-symbol-rendering`). The pattern has been fixed at least five times by hand and never linted.
- **4b. Guard-shape lint.** Where the Ruby method's skeleton contains `ref:respond_to?` or `ref:acts_like?` and the paired TS body contains `instanceof` and no `rbObjRespondTo` / `actsLike`, flag. The skeletons already exist in `call-skeletons.json`; this needs the SKIP suppression from "The call gates have the same hole" lifted for those two names. Catches all 6 DUCK plus `time-zone-converter-cast-missing-infinite-arm`: **7**. Cost: small. Prior art: about ten hand-filed `*-duck-type*` stories in the backlog, no lint. **RFC 0113 is the relevant rejection**: whole-population arm comparison was measured at 75% noise and runs ungated permanently (`0113 README:236-238`). This proposal avoids that by keying on one specific call name, the way the missing-`throw` stratum did (88.4% real, gated by `seed-a-missing-throw-arm-ratchet`).

### 5. Return-shape and block-arm comparer

- **What.** Two facts per matched pair, in the ratchet family. (a) Does the Ruby body's last expression return a value where TS declares `void` or `Promise<void>`? (b) Does the Ruby method take `&block` or call `yield` / `block_given?` where the TS signature has no function-typed parameter?
- **Catches.** (a) `establish-connection-returns-void-not-pool`, `activesupport-assert-not-returns-void-…`, `assert-queries-count-discards-block-result`, `attribute-from-database-forgetting-assignment-returns-self`, plus `dirty-mutation-tracker-returns-plain-hash-not-indifferent` if `with_indifferent_access` in the return expression is tracked: **5**. (b) `find-each-find-in-batches-block-arm`, `has-many-build-accepts-block`, `relation-find-or-create-by-block`, `relation-first-or-create-block`, `hwia-has-no-enumerator-form-…`, `hwia-test-enumerator-…`: **6**.
- **Cost.** Medium. `block_given?` and `&block` are easy in the Ruby extractor. Return typing on the Ruby side is only reliable for the void case, which is why this is scoped to void.
- **Fails by** Ruby methods whose return value is incidental (every Ruby method returns something). Expect a high baseline. Gate only the block check at first; report the void check and measure noise before gating, as RFC 0113 did.
- **Prior art.** `parity:api:params` compares names, not block presence. `runcallbacks-returns-block-value`, `singular-reader-return-type-lie`, `safe-buffer-to-s-returns-self` are hand-filed instances. **No comparer proposed anywhere.**

### 6. Finish `add-error-message-parity-signal` (already filed)

RFC 0127, status `ready`, unstarted. It extracts `raise Klass, "literal"` and pairs it with `throw new Klass("literal")`. It would catch the literal-message half of RENDER (`converge-negative-enum-condition-warning-to-rails`, `activesupport-assertion-failure-messages-…`) and the class half of RAISE where the raise is in the paired body (`pg-translate-no-connection-raises-not-established`, `update-columns-raises-missing-attribute-error`): **about 4 to 5**. Interpolated messages are out of its reach; proposal 3 covers those. `error-class-parity-lint` (0025, done) covers hierarchy only.

## What is not tractable

About 61 stories have no tool, and chasing one would waste time.

- **LANGWALL, 13.** Marshal, Psych YAML, mutable String identity, encodings, `==` through a Proxy, `class_eval` file attribution, sub-nanosecond floats. These need a ratified "cannot converge" decision each, not a detector. Several already contradict a recorded skip reason.
- **TESTSIDE, 18 of 21.** Bespoke models, fake pools, vitest interop, a cross-test spy leak. Only a human comparing the two test bodies sees these. Three (`topic-open-replies-scope`, `visitor-model-drops-password-confirmation-reader`, `client-destroyed-client-ids-hash-default`) are model drift that `parity:fixtures:models` could be extended to catch.
- **QUERY 8 and DRIVER 6.** Query counts and driver quirks need a live database and the specific scenario. The existing query pipeline compares SQL text for one expression and cannot see counts. Extending it to emit a query log per fixture is possible, but the scenarios (`author.no_joins_comments.first` on a loaded owner) are exactly what the Rails tests already encode, so the test is the cheapest oracle here.
- **LOGIC, about 21 of 24.** Stale scope registry inside a callback, through-built records on an unsaved owner, pluck tuple shape on joins. Each is a one-off behavioural bug in a body that calls the right names. Only execution finds them.

Assertion convergence remains the only detector for roughly a third of this class. The realistic goal is to stop spending it on the other half.
